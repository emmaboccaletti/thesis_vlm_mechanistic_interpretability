# MOMENTS overview: the extended codebase

`overview.md` documents the original paper's methodology as embodied in this codebase. The five `original_*.py` files preserve the paper's scripts exactly as published, kept purely for reference and diffing. Every other file in this directory has since been modified or newly added, in two directions:

1. **Model coverage** — `analysis_utils.py` gained a Qwen3-VL loading path alongside Qwen2-VL, Gemma 3, and Pixtral.
2. **The MOMENTS extension** — a new task built on the MOMENTS football-highlights dataset (see `thesis_project/data/moments-dataset-notes.md`), which needed its own prompt loader, token-alignment logic, counterfactual modes, and behavioral/circuit evaluation scripts, since it doesn't fit the fixed-length synthetic-task assumptions the original pipeline was built around. **Only `moments_goal` (binary goal-vs-not-goal detection) has actually been run with generated data** — `data/moments_goal/` is the only MOMENTS data directory present, and every MOMENTS job script passes `--task goal` to `create_moments_dataset.py`. `moments_important` (general highlight/importance detection over the full IM/NIM corpus) and `moments_event_type` (the full 3-way goal/corner/shot classification, as opposed to the pairwise `goal_vs_corner_data.csv`) are supported code paths in `analysis_utils.SUPPORTED_TASKS` but have no corresponding dataset in this repo, so they don't currently run end-to-end. Event-type *behavioral* evaluation (3-way and pairwise) does have real data — it's done by rewriting the question on top of `moments_goal`'s existing `event_type`-labeled CSV rows at eval time (see `evaluate_moments_event_type_behavior.py` / `evaluate_moments_event_type_pairwise_behavior.py` below), not by loading a separate `moments_event_type` task/dataset.

This file documents the current, modified/extended state of the non-`original_*` files. Where a same-named `original_*.py` counterpart exists, the diff between them is described concretely rather than guessed from the filename.

## Core infrastructure (modified from the paper's originals)

### `analysis_utils.py` (vs. `original_analysis_utils.py`)
This is the most heavily changed core file. Concretely, on top of the original `load_model`/`load_dataset` pipeline described in `overview.md`:
- **Qwen3-VL support**: `load_model` now imports `Qwen3VLForConditionalGeneration` (guarded by a `try/except ImportError` so an older `transformers` install doesn't break Qwen2 runs) and picks between the Qwen2 and Qwen3 model classes based on whether `"qwen3"` appears in `model_name`.
- **New `SUPPORTED_TASKS` entries**: `moments_goal`, `moments_important`, `moments_event_type` — but as noted above, only `moments_goal` has an actual dataset generated for it in this repo; the other two are unexercised code paths.
- **`load_dataset` MOMENTS branch**: for any task name starting with `moments_`, the CSV path is resolved from `moments_data_file` or `data/<task>/<moments_cf_mode>_data.csv` (rather than the `<model>_<textual|visual>_data.csv` naming used by the five original tasks), prompts are built via `load_moments_vl_prompts_list` from `moments_utils.py`, and `possible_answers` is fixed per subtype (`yes`/`no` for `goal`/`important`, `goal`/`corner`/`shot` for `event_type`). Four new keyword arguments thread through: `moments_cf_mode`, `moments_max_images`, `moments_total_prompt_count`, `moments_data_file`.
- **Counterfactuals are precomputed for MOMENTS**: the original always calls `setup_random_counterfactual_prompts` after loading; the MOMENTS branch skips this because the counterfactual prompt/answer/images are already encoded per-row in the CSV (this is what lets `moments_cf_mode` express random-pair, language-only-perturbation, vision-only-perturbation, and combined counterfactuals as a data-generation-time choice rather than a runtime one).
- **`load_l_vl_scores`** gained a `scores_dir` parameter so cross-modal analysis can point at a mode-specific MOMENTS results directory instead of always assuming `data/<task>/results/<model>/`, plus an explicit `FileNotFoundError` if either the `l` or `vl` ig=5 score file is missing (the original silently let `torch.load` raise on the first missing file).
- **`get_limited_labels_for_task`** and **`get_parallel_l_prompts`** both grew MOMENTS branches, dispatching to `get_moments_limited_labels` / `get_moments_event_type_limited_labels` / `load_moments_parallel_l_prompts` in `moments_utils.py`.
- Every hard-coded `./data/{task}/...` result path in the discovery/eval, cross-modality, intersection, and backpatching scripts (see below) was made overridable via an `--output_dir` / `--scores_dir` / `--output_file` CLI argument, defaulting to the original path when omitted. This is infrastructure to let many MOMENTS variants (different `moments_cf_mode`, different sigma noise levels, `_withoutPOS` vocab, etc.) write to distinct result directories without clobbering each other, which the fixed original paths didn't need to support.

### `attr_patching.py`
No `original_*` counterpart exists, so this is compared against `overview.md`'s description of the AP-IG method (`node_attribution_patching_ig`) rather than a diff. The method itself — clean/counterfactual forward passes, `diff_cache`, integrated-gradient interpolation, backward-hook accumulation of `activation_diff × gradient` — is unchanged. What's new is defensive shape-checking specifically motivated by MOMENTS: unlike the synthetic tasks (which produce identical sequence lengths for every prompt of a task), MOMENTS transcripts have variable length, so a mismatched clean/counterfactual pair can silently produce garbage attribution or crash deep inside a hook. Three explicit `RuntimeError`s were added — for clean/counterfactual cache-shape mismatch, backward-hook shape mismatch, and backward-hook accumulation shape mismatch — each reporting the offending `clip_id/group_idx/clip_name` from `vl_prompt.metadata` so a bad MOMENTS row can be traced back to source.

### `general_utils.py` vs. `general_utils_WORKING.py`
`general_utils_WORKING.py` is **not imported anywhere** in the codebase (confirmed by grep) — it is an orphaned earlier snapshot of `general_utils.py`, kept on disk rather than deleted. The only functional difference is in `balanced_answers_train_test_split`: `general_utils.py` (the live version) adds a guard so that when a small or class-imbalanced dataset leaves `test_prompts` empty before the train/test rounding-correction step, it re-shuffles and re-splits instead of looping forever / crashing. This matters for MOMENTS subtypes with small prompt counts (e.g. `moments_goal`'s 100-prompt cap) where the original unconditional `while` loop could hang.

Beyond that fix, `general_utils.py` carries several inline `# Added by Emma` / `# EMMA ADDED` comments marking smaller edits (e.g. `get_image_size_for_model` lower-casing the model name before matching, and a GPU-count log line), and a block of memory-debugging helpers at the end of the file — `enable_memory_snapshot`, `gpu_memory_snapshot`, `monitor_out_of_memory`, `monitor_memory` — added to help diagnose the CUDA OOM issues that motivated `attempt_fix_OOM_script_backpatching_experiment.py` (below).

### `evaluation_utils.py`, `component.py`, `metrics.py`, `vision_language_prompts.py`, `visualization_utils.py`, `activation_patching.py`
No `original_*` counterparts exist for these, and no MOMENTS- or model-name-specific branching was found in any of them (checked via `grep -i "moments\|qwen3\|gemma\|pixtral"`, no matches). Their content matches what `overview.md` already documents (`vision_language_prompts.py`'s `VLPrompt`/`vlp_collate_fn`, `evaluation_utils.py`'s `circuit_faithfulness`/`model_accuracy`, `component.py`'s hookable-component wrapper, `metrics.py`'s `logit_diff`/`indirect_effect`/KL/JS divergence, `visualization_utils.py`'s Plotly/CircuitsVis plotting helpers, and `activation_patching.py`'s classic (non-IG) activation-patching experiment). They are reused as-is by the MOMENTS pipeline — MOMENTS-specific logic lives entirely in `moments_utils.py`, `modality_alignment_utils.py`, and the loader/script layer above them, not in this shared machinery.

## Task-specific utilities (existing 5 tasks)

`arithmetic_utils.py`, `object_counting_utils.py`, `clevr_color_ordering_utils.py`, `factual_recall_utils.py`, `sentiment_analysis_utils.py` — no MOMENTS or new-model-specific code was found in any of these (same grep check as above, no matches). They remain the per-task prompt loaders and utilities for the five original reasoning tasks described in `overview.md`, unmodified in substance for this thesis extension.

## Main experiment scripts vs. their `original_*` counterparts

All four scripts below picked up the same three MOMENTS-related conventions: a `--moments_cf_mode {random_pair,language_only,vision_only,both}` flag (default `vision_only`), a `--moments_data_file` override, and (for cross-modality/intersection/backpatching) a runtime-derived MOMENTS token alignment in place of the original's static per-task position tables.

### `script_node_circuit_discovery_and_eval.py` (vs. `original_script_node_circuit_discovery_and_eval.py`)
Smallest diff of the four. Adds `--output_dir` (defaulting to `./data/<task>/results/<model>/`, created if missing) so node scores and faithfulness results can be redirected per MOMENTS variant, and threads `moments_cf_mode` / `moments_max_images` / `moments_total_prompt_count` / `moments_data_file` into `load_dataset`. `--moments_max_images` caps how many of the 10 sampled MOMENTS frames are used per example (useful for cheaper debugging runs); `--moments_total_prompt_count` caps the discovery/eval split size.

### `script_node_cross_modality_analysis.py` (vs. `original_script_node_cross_modality_analysis.py`)
Implements the D/Q/L (data/query/last) cross-modal interchange faithfulness analysis (see `overview.md` for the original method). For MOMENTS, the static `POS_MAPPINGS[f"{model[:4]}_{task}"]` lookup and the static `get_text_sequence_positions`/`get_image_positions` D-span lookups are replaced by `get_moments_alignment_info(...)` from `modality_alignment_utils.py`, which derives the alignment at runtime from an actual tokenized prompt pair (see below — this exists because the Qwen processor inserts the image-token block dynamically, so a hard-coded table isn't reliable for MOMENTS). Also adds `--scores_dir` and `--output_file` overrides.

### `script_node_intersection.py` (vs. `original_script_node_intersection.py`)
Largest diff of the four (166 insertions). The original's `split_to_d_q_g` (splitting circuit components into Data/Query/Generation position groups) only knew how to look up static per-task limits; it now accepts an optional `moments_d_limits` override, threaded through from `get_moments_alignment_info`'s `l_data_limits`/`vl_data_limits`. `get_full_intersection_dict` was extended to: (a) accept `moments_alignment_info` and pass the right D-limits for every one of its many `split_to_d_q_g` calls (circuit heads/neurons, both L and VL, plus the random-baseline circuits used for comparison); (b) log a warning and record per-partition emptiness (`empty_partitions` dict with 12 boolean flags) and per-partition component counts in the result dict — defensive additions because MOMENTS' data-span alignment can legitimately produce an empty partition (e.g. no selected heads falling in the image span) in a way the fixed-length synthetic tasks rarely did. Also gained `--scores_dir` / `--output_file` / `--moments_data_file`, and `remove_pos_info`/`split_to_d_q_g` now guard against empty component lists.

### `script_backpatching_experiment.py` (vs. `original_script_backpatching_experiment.py`)
Implements the layer-window "backpatching" causal experiment (patching a span of layers from the counterfactual run into the clean run). The `backpatching(...)` and `looped_backpatching(...)` functions gained a `moments_alignment_info` parameter: when present, the "data span" positions used to select which sequence positions get patched come from `moments_alignment_info["l_data_limits"]`/`["vl_data_limits"]` instead of `get_text_sequence_positions`/`get_image_positions`. `main()` builds `moments_alignment_info` once (from the first loaded prompt pair) whenever `task_name` starts with `moments_`, and threads it through both the main-circuit and language-baseline backpatching calls. Also added `get_results_path(args)` (respecting a new `--output_dir`) and `--moments_data_file`.

### `attempt_fix_OOM_script_backpatching_experiment.py`
No `original_*` prefix (it's a working variant, not a paper baseline), and it does **not** build on the current `script_backpatching_experiment.py` — diffing the two shows it was branched from an *earlier* version of that script, **before** MOMENTS alignment support existed, specifically to try fixing a CUDA out-of-memory issue: cached activations from `generate_activations(...)` are moved to CPU immediately (`.cpu()`) after being produced, and the specific layer slice needed inside each patching hook is moved back to GPU on demand (`.to(value.device)`) rather than keeping the entire `(n_layers, n_prompts, seq_len, d_model)` activation cache resident on GPU for the whole run. It lacks the later `moments_alignment_info` plumbing and the `--output_dir`/`--moments_data_file` flags that `script_backpatching_experiment.py` has now, so it's best read as a point-in-time OOM experiment (used by `reproducing_code/jobs/attempt_fix_OOM_run_backpatching_exp_qwen_color_ordering.job`) rather than a file that stays in sync with the main script.

### `script_backpatch_vqav2.py`
No `original_*` counterpart — this is a new script adapting the same backpatching machinery to VQAv2 (`VQA_ANNOTATIONS_PATH`/`VQA_QUESTIONS_PATH`/`VQA_IMAGES_PATH` point at a local `./vqa/v2_*` COCO-val2014 VQA install). `load_vqa_dataset` builds up to 3000 single-image VQA examples (one per unique `image_id`, capped at 3000), converts each to a "answer in a single word" chat prompt via `processor.apply_chat_template`, and reuses `to_single_token`/`get_content_key_for_prompt_dict`/`load_image_for_model` from `general_utils.py` and `model_accuracy` from `evaluation_utils.py`. This looks like an out-of-domain sanity/behavioral check on real-world VQA data, run through the same infrastructure as the synthetic and MOMENTS tasks, rather than a MOMENTS script per se.

## MOMENTS-specific new files

These have no `original_*` counterpart — they are the core of the thesis's MOMENTS extension.

### `moments_utils.py`
The MOMENTS-equivalent of the per-task loaders (`arithmetic_utils.py` etc.), but structurally different because MOMENTS prompts come from a pre-built CSV (produced by `thesis_project/data_generation/create_moments_dataset.py`) rather than being generated on the fly.
- `_resolve_paths` / `_split_paths` handle the CSV's `|`-joined frame-path lists and resolve them against several possible repo roots (`thesis_project/`, `reproducing_code/`, `tmp_moments`, `tmp/`), since the CSV may have been generated on a different machine/user path than it's later read from.
- `load_moments_vl_prompts_list(...)` is the main entry point (called from `analysis_utils.load_dataset` and directly from most of the `evaluate_moments_*`/`inspect_moments_*` scripts). For each CSV row it: resolves and loads the clean and counterfactual frame sequences (skipped entirely in `language_only` mode), optionally wraps the raw prompt text in the Qwen chat template via `_build_qwen_chat_prompt` (image placeholders per frame + the question text), and packages everything into a `VLPrompt` with rich `metadata` (`clip_id`, `group_idx`, `clip_name`, `event_type`, `label`, `similarity`, both the `local`/`global` transcript variants, and the `cf_mode` used to generate that row's counterfactual).
- **Counterfactual alignment filtering**: when `check_counterfactual_alignment=True` (the default used by the discovery/eval pipeline), each row's clean and counterfactual prompts are both tokenized and the row is *dropped* if their token lengths don't match — logged via `logging.info` with the offending clip identifiers. This is necessary because AP-IG (`attr_patching.py`) requires clean and counterfactual activation tensors to have identical shapes; MOMENTS transcripts of different length (or a "both" mode where the counterfactual swaps both modalities) can easily break that invariant. Behavioral-only evaluation scripts pass `check_counterfactual_alignment=False` since they only use the clean side.
- `load_moments_parallel_l_prompts` builds language-only counterparts of a list of VL prompts (used for the L/VL cross-modal comparison already implemented in `analysis_utils.get_parallel_l_prompts`).
- `get_moments_limited_labels` / `get_moments_event_type_limited_labels` find which surface forms (`"yes"`, `" Yes"`, `"goal"`, `" Goal"`, ...) tokenize to a single model token, since the faithfulness/attribution machinery needs a fixed, single-token answer vocabulary per task, exactly analogous to how the original tasks constrain their answer sets.

### `modality_alignment_utils.py` — `get_moments_alignment_info`
The original paper's `POS_MAPPINGS` (visible at the bottom of this same file, unchanged) are hand-built, static tables: for each `(model, task)` pair, someone worked out exactly which token positions the image occupies and which text positions the "data"/"query" spans of the prompt occupy, because every prompt for a given synthetic task has an identical template and length. MOMENTS breaks that assumption — variable-length transcripts, a chat-template that inserts a variable-length image-token block, and per-example differences in exact tokenization — so a static table isn't viable.

`get_moments_alignment_info(model, l_prompt, vl_prompt, task_name)` derives the alignment dynamically from one actual tokenized (language-only, vision-language) prompt pair:
1. Tokenizes both prompts and the fixed MOMENTS question suffix (from `MOMENTS_QWEN_QUESTION_BY_TASK`, one canonical question per subtype).
2. Finds the shared chat-template prefix length (`prefix_len`) by walking both token sequences until they diverge.
3. Finds where the VL sequence's suffix re-syncs with the L sequence's suffix (`image_skip`) — everything between `prefix_len` and `prefix_len + image_skip` in the VL prompt is the inserted image-token block (`image_start`/`image_end`).
4. Locates the question-suffix tokens in the L prompt (`question_start`), with a length-based fallback (with a logged warning) if the exact token subsequence isn't found verbatim — some Qwen tokenization paths don't preserve the question text as an exact contiguous subsequence.
5. Builds a `PositionMapping` (the same class the original static tables use) by: mapping the shared prefix 1:1, mapping the post-image text suffix 1:1 (offset by the image block), mapping any trailing VL-only chat-template tokens (e.g. the assistant-generation marker) onto the L sequence's last position, and mapping the L "data" span (prefix→question) many-to-many onto the entire VL image-token span — mirroring how the original static tables map a task's textual data description onto the corresponding image tokens.

It returns a dict with the `pos_mapping` plus explicit `l_data_limits`/`vl_data_limits`/`l_query_limits`/`vl_query_limits`/sequence lengths, which is exactly the shape `script_node_cross_modality_analysis.py`, `script_node_intersection.py`, and `script_backpatching_experiment.py` now consume in place of the static-table lookups, as described above.

### `check_moments_drop_rates.py`
A standalone CLI checker (not part of the main pipeline) that reports, per MOMENTS CSV mode, how many rows would survive the same clean/counterfactual token-length-matching filter that `moments_utils.load_moments_vl_prompts_list` applies — but computed directly through the HF `AutoProcessor` (`processor(images, prompt, ...)` / `processor.tokenizer(prompt, ...)`) rather than through `model.to_tokens`. Reports total/kept/dropped/mismatched/missing-counterfactual counts and prints up to `--show_examples` mismatched rows (with clip identifiers and both token lengths) per mode. Its docstring frames it as checking `random_pair`, `language_only`, and `both` by default (the language-sensitive modes, where a text perturbation can shift token count), noting `vision_only` should stay length-stable.

### `inspect_moments_faithfulness_baselines.py`
A debugging tool for the `moments_goal` / language-only faithfulness pipeline: loads a model, loads the `moments_goal` language-only evaluation split, loads a saved `ig=5` LD node-score file, and for each requested circuit size in `--percentages` (default `[0.3, 0.5, 0.9]`) selects the top-scoring heads/MLP neurons via `get_top_scoring_components` and calls `circuit_faithfulness(..., return_details=True)` to get **per-sample** good/bad/ablated logit-difference values (rather than the single aggregate faithfulness score `script_node_circuit_discovery_and_eval.py` reports). Writes one row per (circuit size, eval sample) to a CSV, so individual MOMENTS clips that behave unusually (e.g. near-zero denominator, or an outlier ablated LD) can be traced back by `clip_id`/`group_idx`/`clip_name` instead of only seeing the averaged faithfulness curve.

### `evaluate_moments_behavior.py`
Measures **clean model behavior** (not circuit faithfulness) on `moments_goal`/`moments_important`: for each prompt, runs the model once and looks only at the final-position logits for the canonical single-token `"yes"`/`"no"` ids (found via `model.to_tokens`, asserting each is exactly one token). Reports overall constrained accuracy, per-class (`yes`/`no`) accuracy, and a target×prediction confusion count, and writes a per-example CSV including both raw logits and the `unrestricted_token_id` the model would have picked with no constraint (a sanity signal for whether yes/no even dominates the model's actual top prediction). `--check_counterfactual_alignment` optionally applies the same drop-mismatched-rows filter as the discovery pipeline, even though only the clean side of each row is used here.

### `evaluate_moments_event_type_behavior.py`
The three-way analogue of the above for `moments_event_type`. Since the underlying CSV/prompt was built around the yes/no `moments_goal` question, `event_type_question(...)` finds and strips the literal suffix `" Is this a goal? Answer yes or no."` from each loaded prompt and replaces it with `" What type of football event is shown? Answer goal, corner, or shot."`, then compares only the final-position logits for the three canonical tokens `goal`/`corner`/`shot` (mapped back to the annotation labels `GOAL`/`CORNER/THROW-IN`/`SHOT-ON-TARGET` via `CLASS_TO_TOKEN`/`TOKEN_TO_CLASS`). Reports overall accuracy, per-class accuracy, an unweighted "balanced accuracy" average across the three classes, and a confusion-count table.

### `evaluate_moments_event_type_pairwise_behavior.py`
A finer-grained variant of the event-type evaluator: for each of the three label pairs (`goal_vs_corner`, `goal_vs_shot`, `corner_vs_shot`), it filters to only the clips belonging to that pair, rewrites the question to a two-way choice (`event_type_pair_question`), and scores accuracy restricted to just those two tokens' logits. This isolates how separable each pair of event types is on its own (independent of the third, potentially easier-or-harder class), rather than only reporting the joint three-way accuracy from the previous script. Writes both a per-example CSV and a `_summary` CSV (overall + per-target accuracy for each pair).

### `analyze_moments_circuit_comparison.py`
A **post-hoc, no-inference** structural comparison across previously-saved MOMENTS results for four conditions: `language_only`, `vision_only`, `both_multimodal`, and `both_text_only` (the last two both read from the "both" counterfactual mode's results directory, but compare its VL-side vs. L-side node scores). For each available condition it loads the saved ig=5 node-score tensor and, per hook, computes `max_abs_score`/`mean_abs_score`/`num_values`/layer index (parsed from the hook name via regex). It then computes, for each pair of conditions and each `--top_k` (default `[5, 10, 20]`), the Jaccard overlap of their top-k highest-scoring hooks **against a random-baseline distribution** (10,000 random same-size draws from the union of all seen hooks, reporting the mean and 2.5th/97.5th percentile Jaccard) — this is what lets the thesis claim an overlap is "more than chance" rather than just reporting a raw intersection count. It also aggregates per-layer score composition and pulls in each condition's faithfulness-vs-circuit-size curve (from the saved `faithfulness_LD_{l,vl}_node_circuit.pt` tuples) into a single `faithfulness_summary.csv`. The docstring is explicit that this is "an exploratory structural comparison, not a causal interchange test" — i.e., it complements rather than replaces the causal cross-modality/intersection/backpatching scripts above.

Alongside the five original tasks' folders sits `moments_goal/`, which holds every MOMENTS counterfactual-mode CSV (`random_pair_data.csv`, `language_only_data.csv`, `vision_only_data.csv`, `both_data.csv`, plus `_sigma0p05`…`_sigma0p5` Gaussian-noise variants and `_withoutPOS` vocabulary variants), a `goal_vs_corner_data.csv`, the cached Qwen same-token-length vocabularies used to build language corruptions, and a `results/` tree.
